配置和插件 ^2.3.0 ​
歡迎使用iztro配置和插件功能。紫微鬥數流派眾多，不同的流派的四化以及星曜亮度都會有些許差異，為了滿足不同流派的需求和功能的擴展，iztro在 v2.3.0 版本加入了全局配置和第三方插件功能。
提示
如果有讀者基於iztro開發了第三方插件開源庫，請 聯系作者 將插件加入到文檔列表以便使用。
配置 ​
關於配置的定義請參考 配置定義。全局配置十分簡單，只需要在調用排盤方法之前調用 astro.config() 方法即可，具體代碼如下：
ts
import { astro } from 'iztro';
astro.config({
mutagens: { 庚: ['太陽', '武曲', '天同', '天相'] },
brightness: {
貪狼: ['旺', '旺', '旺', '旺', '旺', '旺', '旺', '旺', '旺', '旺', '旺', '旺'],
},
});
上述代碼執行之後調用排盤方法時，將會把新的配置合並到默認配置中進行應用。換言之，在數據與默認配置相同的情況下，你並不需要重復在配置文件中設置。關於默認的四化表，請參考 十天干四化表。關於默認星曜亮度，請參考 星曜亮度表。
除 mutagens 和 brightness 外，還可以透過以下選項調整排盤規則：
配置項可選值預設值說明
yearDivide ^2.4.0normal | exactnormal年干支分界；normal 以農曆正月初一為界，exact 以立春為界
horoscopeDivide ^2.4.3normal | exactnormal運限使用的年、月干支分界
ageDivide ^2.4.5normal | birthdaynormal小限虛歲分界；normal 只看自然年，birthday 以農曆生日為界
dayDivide ^2.5.2forward | currentforward晚子時歸屬；forward 歸入次日，current 歸入當日
algorithm ^2.5.0default | zhongzhoudefault安星規則；default 為通行版本，zhongzhou 為中州派版本
注意
從 v2.6.2 開始，astro.config() 僅設定後續新建星盤的預設配置；withOptions({ config }) 僅覆蓋當前星盤，不再寫入全局預設配置。既有星盤及其運限、四化分析保留產生時的配置和語言。若舊程式依賴單次排盤修改全局配置，請改為明確呼叫 astro.config()。
getConfig() ^2.3.0 ​
用途
取得目前已生效的全局配置。傳回的 mutagens 和 brightness 使用函式庫內部的規範化鍵名，適合用於偵錯或確認配置狀態。
^2.6.2 回傳值是獨立深拷貝，修改物件或其中的四化、亮度陣列不會改變函式庫配置。

type getConfig = () => {

dayDivide: 'current' | 'forward';
horoscopeDivide: 'normal' | 'exact';

參數
無
傳回值
目前生效的配置物件

ts
import { astro } from 'iztro';
astro.config({ algorithm: 'zhongzhou', ageDivide: 'birthday' });
const currentConfig = astro.getConfig();
resetConfig() ^2.6.2 ​
恢復預設配置並清除所有自訂四化、亮度表；既有星盤不受影響。
ts
type resetConfig = () => void;
預設分界規則為 yearDivide: 'normal'、horoscopeDivide: 'normal'、ageDivide: 'normal'、dayDivide: 'forward'，安星方法為 algorithm: 'default'。本方法無參數、無回傳值，不重設已載入的插件。
ts
const chart = astro.withOptions({

});
astro.resetConfig();
chart.horoscope('2026-3-1'); // 仍使用該星盤產生時的生日分界配置
插件 ​
iztro的插件就是一個函數，這個函數會掛載到星盤對象上。你可以根據自己的需求擴展功能。假如你是在typescript環境下開發，你需要將插件方法申明到接口中，而該接口需要繼承自 FunctionalAstrolabe。
接口聲明如下：
ts
export interface IAstrolabe extends FunctionalAstrolabe {
myNewFunc: () => string;
majorStar: () => string;
}
上述 myNewFunc 和 majorStar 方法可以根據你自己的需求進行定義。上述接口內的方法你可以在一個插件方法內實現，也可以在多個插件方法內實現。實現方法如下：
ts
// 創建一個插件函數
export function myTestPlugin(this: IAstrolabe): void {
// 實現插件應用邏輯
this.myNewFunc = () => {
return this.fiveElementsClass;
};
}
// 創建二個插件函數
export function myTestPlugin2(this: IAstrolabe): void {
// 實現插件應用邏輯
this.majorStar = () => {
let stars = this.palace('命宮')
?.majorStars.filter((item) => item.type === 'major' && !['祿存', '天馬'].includes(item.name))
.map((item) => item.name)
.join(',');
if (!stars) {
stars = this.palace('遷移')
?.majorStars.filter((item) => item.type === 'major' && !['祿存', '天馬'].includes(item.name))
.map((item) => item.name)
.join(',');
}
return stars ?? '';
};
}
掛載插件的方法也非常簡單，只需要在引入 astro 以後執行 loadPlugin() 或者loadPlugins() 方法即可。兩種方式註冊的插件會套用到後續新建立的星盤實例。
ts
import {astro} from iztro;
// 批量掛載插件
astro.loadPlugins([myTestPlugin， myTestPlugin2]);
// 逐個加載插件
astro.loadPlugin(myTestPlugin);
astro.loadPlugin(myTestPlugin2);
如果只想為一個已經建立的星盤套用插件，可以呼叫該星盤實例的 use() 方法：
ts
const astrolabe = astro.bySolar<IAstrolabe>('2023-10-18', 4, 'female');
astrolabe.use(myTestPlugin);
astrolabe.myNewFunc();
提示
如果在typescript環境下使用插件時，需要將指定範型類型，如此才會在編譯的時候不會出現方法未定義的錯誤。比如我們要使用上述插件方法，需要：
ts
const astrolabe = astro.bySolar<IAstrolabe>('2023-10-18', 4, 'female');
// 使用插件定義的方法
astrolabe.myNewFunc();   // 火六局
// 使用第二個插件方法
astrolabe.majorStar();   // 七殺

紫微鬥數運限 ​
運限的分類 ​
如果把 本命盤 比作一張出生時就定下來的地圖，那麼運限就是你在不同時間走到地圖上不同區域的過程。本命盤描述的是一個人的基礎設定、慣性和可能性；運限描述的則是：這些特質在什麼時間比較容易被觸發。
紫微鬥數的運限可以一直細分到 流分、流秒，但看得越細，偶然因素就越多，解釋也越容易失真。日常解盤時，重點掌握下面五種就夠了：
大限：一個大限管十年，是運限判斷的主軸。大限從命宮起，陽男陰女順行，陰男陽女逆行；第一大限從幾歲開始，由 五行局 決定。
小限：一年走一宮，用虛歲計算。它的起點由出生年地支所屬三合局決定，男性順行、女性逆行，具體排法可參考 起小限訣。
流年：一年的主題盤。流年命宮按當年地支落宮，每年順行一宮；它會產生當年的 流曜 和 流年四化。
流月：把流年的主題繼續拆到一個月。它適合觀察某件已經有跡象的事在什麼月份更容易推進，而不適合脫離大限、流年單獨斷大事。
流日、流時：將時間再縮小到一天和一個時辰，通常用於擇時或復盤具體事件。初學者很容易在這裡看花眼，建議先把大限和流年練熟。
大限、小限和流年並不是三張互相替代的盤。它們的關係更像是：大限給出十年的大環境，流年標出當年的重點，小限則補充這一年個人更容易被牽動的落點。比如大限走到官祿宮，並不代表十年裡每天都只發生工作上的事；但工作、方向、責任和社會角色，確實更值得在這十年裡重點觀察。
《紫微鬥數全書》對起大限的規則概括得很直接：
大限由命宮起，陽男陰女順行；陰男陽女逆行，每十年過一宮限。

運限的作用 ​
很多人拿到命盤後，最想問的是「我什麼時候發財」「什麼時候結婚」「什麼時候換工作」。這類問題真正要靠運限來回答。本命盤像是食材，運限更像火候；同樣一塊食材，火候不同，做出來的東西當然不一樣。
運限的作用，不是把未來寫成一張不能修改的劇本，而是幫助我們判斷某一階段更容易出現什麼主題、什麼阻力，以及自己應該把注意力放在哪裡。它至少有三個作用：
找出階段主題。 大限命宮走到哪個本命宮位，就會把那個宮位的議題放大。走到官祿宮，不等於一定升職；走到夫妻宮，也不等於一定結婚。它們更像是在提醒你：這十年裡，事業定位、合作關係、親密關係等問題會比較佔據精力。
判斷事情的節奏。 大限先看「有沒有這類機會」，流年再看「今年是否被點燃」，小限和流月用來縮小時間範圍。先有十年的土壤，再有一年的雨水，事情才比較容易真正發生。
識別風險和資源。 當某個運限同時會到吉星、吉化，往往意味著資源、支持或選擇空間更多；遇到煞忌時，也不等於必然出事，而是更需要重視成本、情緒、合約、健康或人際摩擦。看到了風險，提前準備本身就是運限最實用的意義。
古書在論大限時反覆強調不能只看一層：
須詳大限獨守吉凶何如，小限獨守吉凶何如，太歲獨守吉凶何如。如歲限俱凶則凶。
又看大限與小限相逢吉凶何如，大限逢太歲吉凶何如，小限逢太歲吉凶何如，禍福所定。
這段話放到今天，最值得學的不是「吉凶」兩個字，而是它的思路：不要看到一顆流年化忌就自己嚇自己，也不要看到一顆流年化祿就躺著等好事。一個判斷至少要讓本命、大限、流年三層資訊互相印證，才比較有參考價值。
運限的運用 ​
運限最怕的用法，是跳過本命盤，直接拿某一年去套斷語。這樣做就像不看地圖、不看天氣，只憑日曆決定要不要出門，命中率當然不會太高。比較穩妥的運用順序如下：
先看本命盤。 先把命宮、身宮和十二宮的基本特質搞清楚，尤其要知道哪些宮位是自己的長項，哪些是容易反覆卡住的課題。沒有本命盤做底，運限就沒有落點。
再看大限命宮及其三方四正。 大限命宮落在哪個本命宮位，就先看該宮的主星、輔星、煞忌與本命四化；然後再看大限命宮的三方四正。它決定的是十年主線，不要只用一個宮位下結論。
疊加流年。 流年命宮落入大限的哪個位置、流年四化飛到哪裡、流曜有沒有觸發本命或大限的重點宮位，才是判斷當年事件的關鍵。大限很好而流年普通，往往是穩步累積；大限壓力大而流年有吉化，也可能是在壓力中找到突破口。
最後用小限和流月收窄。 當你已經知道「這十年大概會處理什麼、這一年大概會發生什麼」以後，再用小限和流月觀察更具體的時間窗口。小限不產生自己的流曜和四化，不要把它當成另一張獨立的流年盤。
舉個不那麼玄的例子：如果一個人大限命宮走到本命官祿宮，流年又讓化祿、化權會到官祿或遷移，這一年就比較適合主動爭取職位、專案、客戶或更大的舞台；如果同時又有煞忌牽動，那麼「機會大」與「壓力大」往往會同時出現。此時最有用的建議不是說「你一定升職」或者「你一定倒楣」，而是提前補齊能力、核實權責、控制節奏，別讓機會變成過度消耗。
提示
看運限時，建議把正在發生的事記下來，隔一兩年回頭驗證。紫微鬥數不是填空題，盤面顯示的通常是一種傾向和情境，而人對機會的選擇、對風險的管理，都會改變事情最終的表現形式。
最後再重複一次：運限不是用來製造焦慮的。看到好年份，認真準備、主動把握；看到壓力大的年份，放慢重大決策、留出現金和精力餘量。能把這件事做到，已經比只會背斷語有用得多了。
