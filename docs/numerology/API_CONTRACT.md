# Numerology API — core + grid/cycles/pinnacles schema 1.2.0

Implemented endpoints: `GET /api/numerology/profiles` and `POST /api/numerology/calculate`. The profile is experimental product-spec arithmetic; eligible original reflective editorial is labelled experimental_editorial; unavailable/unsupported33 content remains null/withheld. There is no persistence or AI. Pinnacle stages and challenges 1–8 have experimental editorial in catalog 1.2.0. Challenge 0 stays withheld. A versioned original-editorial catalog and GETmeanings endpoint use a separate source/review/publication gate; unreviewed material is withheld.

POST JSON:

```json
{"birthDate":{"year":1990,"month":6,"day":15},"fullName":"Nguyễn Văn An","profileId":"pythagorean-vn-v1","profileVersion":"1.2.0","locale":"vi-VN"}
```

Only birthDate is required. FullName is optional; omitted/blank gives unavailable name metrics. The other fields select the currently sole allowlisted profile/version/locale. Integers are required for year/month/day. Optional `targetDate` is strict YYYY-MM-DD, a valid Gregorian date from birth through2199. If omitted, use captured referenceDate. No client-supplied results, birthGrid, cycles, normalizedName, referenceDate, hour or gender. Future birth dates rejected against a reference date captured once in Asia/Ho_Chi_Minh, returned in the response and injected into the pure engine.

Success returns `ok`, schemaVersion, experimental profile metadata, referenceDate, `contentVersion` (`1.2.0` for the eligible original editorial bundle, including stage pinnacle and challenge readings; null when the publication gate fails), seven metrics, birthGrid, personal year/month/day cycles, pinnacles, normalized `nameAnalysis` for the user's calculation trace, capability states and policy warnings. Each available metric carries rawTotal, parts, reduction steps, rootValue and master status. No raw entered name is echoed; normalized name and numeric traces are private response data, not public catalog data.

Errors: `{ok:false,error:{code,message,fields:[{path,code,message}]}}`; 400 body/date/name/locale/client-result/JSON or corrupt/truncated/dictionary-dependent compressed body (`INVALID_BODY_ENCODING`), 404 unknown profile/version, 413 existing 256kb parser limit, 415 unsupported charset (`UNSUPPORTED_CHARSET`) or content encoding (`UNSUPPORTED_ENCODING`), 429 `RATE_LIMITED` with `Retry-After`, 500 generic calculation failure. Parser errors use fixed messages and empty fields; internal error details are withheld. Numerology error translation is scoped so existing Tu Vi error shapes remain unchanged.

All numerology responses, including parser errors, 429 responses and CORS OPTIONS preflight responses, use `Cache-Control:no-store`. The existing logger records method/path without query/body; no name/date persistence is added. POST results must not be copied into URLs or shared browser storage by frontend. `GET /profiles`, `GET /meanings/:metricId/:value` and `POST /calculate` share one in-process fixed window, default 120 requests per 60 seconds. The key is the direct socket address. `X-Forwarded-For` is ignored unless `NUMEROLOGY_TRUST_PROXY=1` and `X-Numerology-Proxy-Token` matches `NUMEROLOGY_PROXY_TOKEN`; the trusted key is then the rightmost forwarded hop. A missing or wrong token keeps the socket key, so a client cannot mint new buckets by sending the header. This window is per process. More than one instance needs the same limit at the reverse proxy. The limiter is not production multi-instance enforcement by itself.

Advanced response: `birthGrid` has version1.0.0/layoutVersion3-6-9-v1/policyddmmyyyy-zero-excluded-v1, all9counts, presentDigits/missingDigits/ignoredZeroCount, layout, `lineLayer` (`arrow-labels-vn-v1` plus a disclaimer) and eight{id,digits,state,note}lines. The note is a Vietnamese presentation label, not a Pythagorean result, and empty cells are not weaknesses. `nameChart` is `pythagorean-letter-count-v1` or `unavailable` when the name is missing. `combinedChart` is `birth-name-presence-v1` with per-digit birth count, name count and presence `both|birth|name|neither`, or `unavailable` without a name. `cycles` has version1.1.0/calendar-year-v1, exacttargetDate and year/month/day, personalYear/Month/Day metrics with ordinary reduction/trace, plus `yearBand` (nine years) and `months` (twelve months of the selected year) computed with the same formulas. Each band cell has `viewDate`: a target on or after the birthday, or `null` when that year or month is entirely before birth. The client sends `viewDate` and does not invent one. `pinnacles` has version1.0.0/policy component-reduce-root-age-v1, reduced month/day/year components, four periods with pinnacle, challenge, inclusive ages, date bounds, and exactly one active period at `asOf` (the same target date as cycles). Challenge value 0 is retained and its meaning stays withheld. Eligible pinnacle and challenge values carry catalog 1.2.0 editorial. Invalid target returns400 INVALID_TARGET_DATE with fieldpath targetDate. Target default uses capturedreferenceDate exactly once; targetfuture is permitted, futurebirth is rejected. Client-injected advancedresults, including `pinnacles`, `nameChart` and `combinedChart`, are rejected400. Activeprofile1.2.0; explicit inactive1.1.0 or1.0.0 returns404 to avoid silent version changes.

GET `/api/numerology/meanings/:metricId/:value` uses the same cataloggate as calculate. Allowlist is the seven core metrics, personal year/month/day, `p1`–`p4` and `challenge`. Numeric values are 1–9/11/22/33 where that metric supports them. Challenge accepts 1–8 only. Malformed or unsupported combinations return 404 MEANING_NOT_FOUND. OptionalprofileId/profileVersion/locale are allowlisted and mustmatchactiveconfiguration; unknownquery/draft/approvalflags400, unsupportedprofile404/locale400. Repeatqueryarrays are rejected. Valid33 returnsnull/withheld (source_unavailable oncecatalogreviewcomplete), neverroot6content. Eligiblemeaning has kindoriginal_editorial, experimental_editorial status, context-specifictitle/summary/reflectionPrompts/limitations, community_reference evidence and pinnedsourceReferences withrelationshipgeneral_number_theme; expertVerifiedfalse. Draft/unapproved/uncheckedsource/profilemismatch stayswithheld; contentVersionnull unlessactualeligiblebundlepublished. Headersno-store includingGET/errors unchanged.

Active original editorial bundle `1.2.0` keeps the 102 core and cycle articles and adds 44 pinnacle-stage readings plus 8 challenge readings. Challenge 0 and number 33 stay withheld. Line notes are a separate `arrow-labels-vn-v1` presentation layer on the birth grid. No external expert or physical-book validation claim, and no source-formula upgrade.
